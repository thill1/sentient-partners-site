# Sentient Partners Website Design Foundation

This document is an addition to, not a replacement for, any existing `CLAUDE.md` instructions. Before editing, inspect the repository and reconcile existing guidance.

## Identity and positioning

Sentient Partners is a founder-led strategic advisory and technology implementation partner, based in Auburn, California. Positioning: **Global Experience. Local Impact.** Tagline: **Strategy | Intelligence | Results**. The website should lead with client outcomes, clarity, sound judgment, and personal accountability, not with AI tools. Reference `design-foundation/brand/Sentient_Partners_Brand_GTM_Foundation.pdf` for approved narrative.

Founder narrative: international executive leadership and mission-critical business and technology operations across major industries. Keep employer names and detailed credentials in the About/bio content, not the hero. Be accurate; do not embellish.

## Visual direction

Use the exact user-provided California photos in `design-foundation/references/original-photography/`: `golden-gate-fog.jpg` for the cinematic opening, `redwoods.png` for depth and founder perspective, and `downtown-auburn.png` for local roots. Use `design-foundation/references/design-comps/` as visual inspiration, not literal copy to trace. Verify image licenses/credits and file sizes before publishing. Do not invent substitute client brands, testimonials, or project outcomes and present them as real.

Visual style: official SP identity, deep navy, champagne, ivory/cream, charcoal; elegant editorial serif display typography and readable sans-serif UI; purposeful photography, uncluttered grid, mature generous whitespace, controlled contrast, responsive image cropping. California landscapes are editorial anchors, not repetitive banners.

## Strict constraints

- No extraneous badges, floating labels, decorative status pills, unnecessary captions, filler microcopy, or ornamental embellishments.
- No generic AI aesthetic: no neon glow, robot heads, circuit boards, sci-fi dashboards, or unrelated network animations.
- No excessive motion: preserve reduced-motion preferences, avoid autoplay audio/video and distracting scroll effects.
- Do not turn the entire homepage into a technical demo. Keep working tech inside contained capability cards.
- Do not foreground Hewlett-Packard, E*TRADE, airline names, or Olympic work in the homepage hero. Put factual detail in the bio as appropriate.
- No client screenshots, real client names, logos, proprietary data, or quotes without authorization. Use clearly labeled fictional demos and synthetic data.
- No invented conversion metrics, reviews, availability, or live integration claims.
- No production deploy, merge to main, or destructive git actions without explicit approval.
- Do not overwrite existing repository instructions; add this content or link to this file.

## Homepage hierarchy

1. Immersive Golden Gate hero: **Global Experience. Local Impact.** Clear business-oriented statement and consultation CTA.
2. Brief editorial firm introduction: strategy and execution, less tool jargon.
3. Eight interactive capability cards (spec in `design-foundation/CAPABILITY_CARDS.md`). Desktop 4x2; adapt responsibly to mobile.
4. Four firm capabilities: Attract & Convert, Automate & Communicate, Operate & Scale, Advise & Grow.
5. Understated founder perspective with redwoods.
6. Local roots using actual downtown Auburn photo.
7. Discover, Strategize, Implement, Optimize process.
8. Quiet, personal CTA with existing booking integration.

## Workflow and quality gate

Use existing `frontend-design` and `hyperframes` capabilities selectively. Frontend design is primary, Hyperframes only for purposeful polish. Inspect git status, all local branches, uncommitted changes, current dependencies, content and assets first. Preserve and reuse functional integrations. Build on an isolated branch without overwriting ongoing design work. Implement layout and all eight visually convincing cards before adding complex interactions. Use a browser/screenshot feedback loop if available; verify desktop 1440px, tablet 768px, mobile 390px. Check keyboard focus, semantic labels, color contrast, reduced motion and performance; run repository lint, typecheck, tests, build. Report outcomes honestly.
