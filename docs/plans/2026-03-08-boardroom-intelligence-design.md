# Sentient Partners Boardroom Intelligence Design

## Objective

Redesign the Sentient Partners website and admin experience so the brand feels like a premium advisory firm with operator-grade clarity, not a generic AI startup or standard SaaS marketing site.

The redesign should communicate executive trust, high-stakes clarity, and strategic control.

## Design DNA

- Voice: premium advisor
- Visual world: strategy deck
- Unforgettable detail: executive intelligence
- Emotional tone: high-stakes clarity
- Chosen execution direction: Black Ledger

## Core Experience Goal

The public site should feel like an executive briefing for growth operators.

The admin should feel like a command room for publishing strategic signals.

The overall experience should feel:

- credible
- composed
- information-rich
- decisive
- premium

It should not feel:

- startup-flashy
- trend-chasing
- generic SaaS
- overly soft or playful

## Visual System

### Typography

Use an editorial or high-contrast display face for major headlines and a disciplined sans-serif for UI and body text.

Typography should feel like:

- executive communication
- boardroom briefing
- premium consulting materials

Headlines should read like decisions and strategic framing, not generic marketing slogans.

### Color System

Use a restrained palette centered around:

- deep ink
- graphite
- paper
- muted steel
- one controlled signal accent

Color should function as intelligence and status, not decoration.

Avoid glow-heavy AI color language as the primary identity.

### Chosen visual execution: Black Ledger

Black Ledger is the approved expression of the design DNA.

It should feel like:

- a confidential executive briefing
- a strategic operating document
- a premium advisory layer over a business system

It should not feel like:

- a flashy AI startup
- a dashboard product
- a conventional services landing page

Core visual traits:

- black ink, graphite, midnight slate
- warm white, pale stone, cool gray typography
- one restrained signal accent
- thin dividers and framed intelligence panels
- minimal shadow, strong structure
- slow, precise, confident motion

### Surfaces

Use layered, structured panels and controlled separators.

Surfaces should feel like:

- briefing cards
- intelligence layers
- strategic artifacts

Avoid soft, default SaaS card styling.

### Motion

Motion should be minimal, precise, and narrative.

Use motion for:

- signal activation
- panel reveal sequencing
- emphasis
- controlled state transitions

Use one signature motion moment rather than many ambient effects.

## Homepage Direction

The homepage should behave like a briefing sequence, not a stack of marketing sections.

### Narrative structure

1. Strategic signal bar
2. Briefing hero
3. Operational problem framing
4. System response
5. Proof layer
6. Conversion layer

### Homepage module hierarchy

1. Signal strip
2. Header / command bar
3. Briefing hero
4. Operational friction
5. System architecture
6. Proof and outcomes
7. Engagement decision

The homepage should follow a disciplined narrative:

- signal
- diagnose
- architect
- prove
- decide

### Hero concept

The hero should be a split-screen executive briefing.

Left side:

- sharp positioning statement
- concise business consequence
- one primary CTA
- one secondary action
- 2-3 operator-grade proof signals

Right side:

- a premium intelligence panel
- a composed system snapshot
- a visual showing how inbound demand becomes qualified and booked opportunity

This right-side artifact should be the most memorable visual element on the site.

### Black Ledger hero definition

The hero should feel like the opening page of a confidential growth briefing.

Left panel:

- compact signal label
- decisive headline
- short business-consequence subhead
- one primary CTA
- one secondary action
- two to three compact proof markers

Recommended CTA structure:

- Primary: `Request AI Opportunity Review`
- Secondary: `See How The System Works`

Recommended proof-marker direction:

- missed-call recovery
- lead routing intelligence
- automated follow-up control

Right panel:

- framed intelligence artifact
- demand
- qualification
- routing
- booked call
- follow-up status

The right-side panel should feel like a premium operating snapshot rather than a fake product dashboard.

### Hero motion

Use one signature activation sequence:

- signal strip appears
- headline resolves
- intelligence panel activates in sequence
- the route from inbound demand to booked call becomes visible

No noisy looping animation should compete with the content.

### Mobile hero behavior

On mobile, collapse the hero into:

1. signal label
2. headline
3. subhead
4. CTA block
5. compressed intelligence artifact

### Problem framing

The page should diagnose business leakage before listing capabilities.

It should make clear:

- where revenue is lost
- how missed calls and slow follow-up affect growth
- why disconnected systems create operational drag

This section should feel like an operator's problem map, not a generic marketing explainer.

### System response

Services should be reframed as one integrated operating model, not a list of separate offer cards.

The site should show how:

- voice
- chat
- web
- follow-up

work together as one business system.

### System architecture section

This section should communicate that the real problem is a broken response system, not isolated point failures.

Recommended title:

- `Revenue Response Architecture`

Recommended framing line:

`Most businesses do not have a lead problem. They have a response architecture problem.`

Recommended system pillars:

1. Demand Capture
2. Qualification Intelligence
3. Routing and Booking
4. Follow-Up Control

This should be presented as one connected system diagram or architecture panel, not four unrelated feature cards.

Recommended interpretation line:

`Voice, chat, web, and follow-up only create leverage when they operate as one response system.`

### Proof

Proof should feel closer to case-study snapshots than a generic testimonial wall.

Use:

- before/after framing
- operational outcomes
- measurable impact
- selected supporting quotes

### Proof and outcomes section

This section should feel like evidence in an executive briefing.

Recommended title:

- `Measured Operational Lift`

Recommended proof structure:

- outcome-led proof blocks
- before / after contrasts
- metrics with context
- quote fragments as support, not as the main structure

Tone should remain:

- sober
- evidence-led
- operational
- commercially relevant

### Conversion

The site should emphasize one primary engagement path.

Likely choices:

- request an AI blueprint
- book a strategy call

Everything else should support the chosen path rather than compete with it.

### Engagement decision section

The homepage should end with a decisive executive next step, not a generic CTA panel.

Recommended title direction:

- `Start With An AI Opportunity Review`

Recommended section contents:

- one decision headline
- one concise "what you get" block
- one urgency line tied to economic and operational loss
- one dominant CTA
- one secondary CTA

Recommended CTA hierarchy:

- Primary: `Request AI Opportunity Review`
- Secondary: `Book Strategy Call`

## Homepage Changes To Prioritize

- Replace generic centered hero composition with a split briefing layout
- Reduce repeated card-grid patterns
- Compress or combine sections with overlapping messages
- Elevate proof and operational framing
- Make the top-of-page experience feel more strategic and less promotional
- Replace generic services framing with architecture framing
- Make the right-side hero artifact the visual anchor for the site

## Admin UI Direction

The admin should feel like a private publishing console for executive signals.

### Core principle

The public site is the briefing.

The admin is the command room.

### Layout direction

Move toward a more productized control layout:

1. navigation or command bar
2. focused editing surface
3. persistent live preview

### Black Ledger admin expression

The admin should feel like the internal control layer behind the public briefing.

The public site says:

- here is the signal
- here is the architecture
- here is the proof

The admin says:

- here is what is live
- here is what changes next
- here is how the signal is controlled

### Interaction goals

The admin should clearly communicate:

- current state
- unsaved changes
- saved status
- content preview

The first redesign priorities should be:

1. persistent preview panel
2. stronger hierarchy and grouping
3. clearer save state and last-updated treatment
4. Black Ledger control-surface styling
5. scalable section navigation

### Visual goals

The admin should share the same Boardroom Intelligence DNA, but in a quieter and more restrained way than the public site.

It should feel:

- precise
- premium
- deliberate
- trustworthy

Suggested admin structure:

1. Command header
2. Left navigation rail or structured tab system
3. Primary editing surface
4. Persistent preview panel

### Admin priorities

- stronger information hierarchy
- persistent preview
- clearer save and publish feedback
- more refined field grouping
- less generic internal-tool styling

## Anti-Patterns To Avoid

- generic SaaS glow language
- default Tailwind or default component-library aesthetics
- repetitive equal-weight card grids
- over-animated sections
- decorative dashboard tropes without strategic purpose
- startup-style AI visual clichés
